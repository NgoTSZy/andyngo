## §0 缺口是什么

ISS-096 修好了「载体恒 exit 0」，但它自己留了一句：

> **仍然未做的**：`SKIP` 段（某项因文件不存在而跳过）**不计入 `FAILED`** ——
> 即「**跑不成**」与「**跑了且不合格**」在本载体里仍**只在 rc 层面部分分开**（`2` 拒跑还没进退出码）。

**实测确认**：载体有 **14 处** `SKIP` 分支（`echo "SKIP …"`），它们**不打印 `EXIT=` 行**：

```
    echo "SKIP 无 acceptance.js"
```

→ `SEGS` 数不到它、`FAILED` 也数不到它 → **载体照样 rc=0**。

于是「这一段**根本没跑成**」与「这一段**跑了且合格**」在**机器读的那一半**里长得一样
（都只是「少了一条 `EXIT=` 行」）。**这是 ISS-096 的同族假绿，只是换了个入口。**

## §1 改了什么（最小改动）

### 1.1 载体 `skills/andyngo/scripts/andyngo-audit.sh`（347 → 382 行 · CHG-172）

| 步骤 | 内容 |
|---|---|
| ① | 加 `SKIPPED=0` 与 `skip()` —— **与 `seg` 对称**：`seg` 记「跑了的结果」、`skip` 记「没跑成」 |
| ② | **14 处** `echo "SKIP …"` → `skip "…"` |
| ③ | 收尾**三态**：`FAILED>0 → 1` · 否则 `SKIPPED>0 → 2` · 否则 `0` |
| ④ | 文件头补「ISS-096 剩余缺口」段 + 三处注释同步 |

**`0` 那一支的文案一字未改**（`载体退出码 **0**：全部 $SEGS 段 \`EXIT=0\`。`）——
保住「人读的那一半」。

**优先级：`FAILED` 优先于 `SKIPPED`** ——
「有段不合格」是**确定**的信号、「有段没跑成」是**缺失**信号；确定的负面优先，
且**两者都不是绿**；报告里两个数都印出来，**不丢信息**。

`2` = **拒跑 / 结果不完整** —— 与 automation §六 铁律「0 通过 / 1 失败 / 2 拒跑」一致，
也与 `write-lock.js` / `alloc.sh` 的 `2` 同族。

### 1.2 尺子 `.check/tests/audit-exitcode-test.sh`（129 → 144 行 · CHG-173）

**加第 ⑤ 组断言**：假成功那跑报告里必须有 `SKIP` 行 **且** 载体 rc=2。
没有它，把 `SKIP` 写回「只打印、不计数」就能让 ①②③④ 全过。

**★ ③ 的期望值必须同时精确化**：原 ③ 断言「假成功 → 载体 **rc=0**」——
而**假根下其余各段都 `SKIP`** → 按新语义假成功那跑**应当是 rc=2**。
**照抄「= 0」会把正确的行为判成红。**

> ③ 的本意（原文）：「没有它，把收尾写成 `exit 1` 就能让 ①②④ 全过（**门被写成什么都报红**）」
> —— **`≠ 1` 才是它的原话**，`= 0` 只是旧语义下的期望值。

## §4 ★ 脚本自己的断言拦下一次真 bug（留证）

我原本的改动顺序是：**先插 `skip()` 函数 → 再转 14 处调用**。
而 `skip()` 函数体里那一行：

```bash
  echo "SKIP $*"
```

**同样匹配转换正则** `^(\s*)echo "SKIP (.*)"$` → 会被改成 `skip "$*"` → **无限递归**。

断言当场拦下：

```
断言失败 [D-skips]：转换了 15 处（期望 14）
  —— [66, 79, 105, 124, 147, 164, 189, 215, 217, 260, 262, 302, 318, 338, 348]
```

**未写盘**（脚本只在最后写文件）。改成「**先转调用、再插函数**」后通过。

**教训**：「新加的代码会被自己写的批量替换规则命中」——
批量替换前先想一遍「我要加的东西会不会也匹配这个模式」。

## §6 仍然未做的（如实登记）

1. **载体没有「预期段数」的硬编码断言** —— 若某一段被**整段删掉**（不是 `SKIP`），
   `SEGS` 只是少一条、`FAILED` 与 `SKIPPED` 都数不到，**rc 仍可能为 0**。
   这是**另一个**缺口：「段数」与「段号是位置别名」（DEC-039）耦合 ——
   写死一个 `EXPECTED=17` 会新增一个**会腐烂的数字**，且段号已被 5 处以上引用。
   **本轮不扩面**（按用户长期指令「慢慢逐步推行，用最少的资源、改动」）。
2. 本轮的 `2` 只覆盖「**本机没有这个件**」这一类 `SKIP` ——
   载体**不区分**「这个件是可选的（如规格，不是每台机器都有）」与「这个件是必需的（丢了要修）」。
   两类都报 `2`。**这是刻意的**：宁可报「结果不完整」，不要报「通过」。
   若将来要区分，需要一份「必需件清单」—— 那又是另一个会腐烂的数字。
