## §1 先判「钩子是不是真的坏了」（两条反证）

**判据一：宿主的活动进程仍在写它「09-16 打开的那份日志」。**

```
grep -h 'HookExecutor. spawn' logs/2026-09-16/*.log | wc -l   →  803
（对照：2026-09-16T15:59Z 那次 acceptance 报的是 798）
```

→ **跨过午夜后又多了 5 次**。若钩子真的停了，这个数不会涨。

**判据二：钩子自己的留痕在午夜后仍在产出。**

自述日志末行 `ts=2026-09-16T16:02:05.192Z` = 本地 **00:02**；行数 1207 → **1211**。

**结论：钩子在跑。`[99]` 报的是假红。**

## §2 根因（一条）

```
ls -d logs/*/                 →  … logs/2026-09-16/ · logs/2026-09-17/
ls logs/2026-09-17/           →  只有 sdk/          （00:00 创建）
ls logs/2026-09-17/*.log | wc -l →  0
```

`host-log.js` 的 `scanHostLogs()`（第 721 行）：

```js
const day = days[days.length - 1];      /* ← 取「最新日期目录」，不取「最新有内容的」 */
```

→ 午夜一过，`logs/2026-09-17/` 存在但**顶层一个 `.log` 都没有** → 只能扫到
`logs/2026-09-17/sdk/conversations/*.log`（16 个文件 · 49 MB）—— 那里**不含** `[HookExecutor] spawn` 行
→ 数到 **0**。

而**自述是累积的**（1211 行，不按天截断）→ **两边窗口不同，比较必然失败**。

**所以这不是「钩子坏了」，是「判据拿一个按天重置的窗口去比一个不按天重置的累积量」。**
