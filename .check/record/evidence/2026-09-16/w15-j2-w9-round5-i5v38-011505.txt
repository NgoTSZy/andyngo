【2】F-H1 的修法：口径归位（不是「放宽」，是「把约束放回它该在的地方」）

规格原文（`skills/andyngo/references/andyngo-event-protocol.md`）：
```
第 14 行  | evidence_ptr | 子代理 | 必须真实存在 |
第 24 行  2. 证据写磁盘，路径放 evidence_ptr（必须真实存在）
```
**只说「必须真实存在」，没有说必须是文件。**

三条约束的**正确归属**（这才是「一个标签只指一件事」的完整版）：

| 问题 | 归谁 | 依据 |
|------|------|------|
| 这个路径**存在**吗？ | **I3** | event-protocol.md:14/24 原文 |
| 这个留证**按约定命名**了吗？ | **D3**（或逐条豁免） | 留证命名约定 |
| 这份留证是**非空文件**吗？ | **D5** | 「证据」这个概念的门槛 |

修法：
```js
// I3：撤回 isFile，只判存在
const missing = [];
for (const l of evtLines) {
  const ev = l.split(/\s+/)[7];
  if (!ev || ev === '--') continue;
  const p = path.isAbsolute(ev) ? ev : path.join(HOME, ev);
  if (!statOf(p)) missing.push(ev);           // ← 只判存在
}
// D5：精确化 —— 零字节 / 是目录 / 不是普通文件，三标签分开
const d5bad = A.map((a) => {
  const st = statOf(path.join(evDir, a));
  if (!st) return null;                       // 读不到属性 → 不在这里重复报（存在性归 I3、归属归 D6）
  if (st.isDirectory()) return { a, why: '是目录' };
  if (!st.isFile()) return { a, why: '不是普通文件' };
  if (st.size === 0) return { a, why: '零字节' };
  return null;
}).filter(Boolean);
```
  **原 D5 的三个毛病**（W9 指出、我复核确认）：
    ① **目录**在 Windows 上 `size` 也是 0 → 一个名为 `w1-j1-a.txt` 的目录被报成「**零字节**」，
       **标签与事实不符**（它不是零字节，它根本不是文件）；
    ② `catch → true` 把「读不到属性」也算成零字节 —— 同一个标签又指了第二件事；
    ③ 它现在**承接**了原先错放在 I3 的「必须是文件」这条约束。
  **双重计数一并消失**：I3 与 D5 不再对同一事实各报一次。

【4】F-H3 的修法：一个探针，两个调用者

```js
/* 原先 I3 用 fs.existsSync，I7 用 existsSync + statSync 两段 —— 两个探针在**设备路径上结论相反**：
   `//./NUL` 的 existsSync 返回 false 而 statSync 成功 → 走进 missing 分支，
   oddArt（「既非文件也非目录」）那条分支**在 Windows 上不可达**。
   一个永远不可达的分支 = 一条永远绿的断言（DEC-019 的同族）。 */
function statOf(p) { try { return fs.statSync(p); } catch (e) { return null; } }
```
I3 与 I7 都改用它。**一份实现，两个调用者** —— 同 ISS-013 那次抽 `fmtLoc` 的道理。

【5】F-H4 的修法：把「跑不跑」从环境变量手里拿回来

原写法（v3.4）用 `ANDYNGO_BIDI_NO_NEST` 环境变量防递归 —— W9 的两条复现：
```
(a) ANDYNGO_BIDI_NO_NEST=1 bash i5-bidirectional-test.sh …  → R33 被静默跳过，断言数 264→263，
    结论照样「全通过」  ← **把没跑报成通过**（ISS-015 的同一形状，换了个入口）
(b) cp 脚本到别处 → SELF_DIR 推导错 → 嵌套调用 rc=127 → [ 127 != 2 ] → PASS  ← 根本没启动也算过
```
修法：
```bash
# ① 防递归改用**第 4 个位置参数**（环境变量设不了它）
if [ "${4:-}" = "--no-nest" ]; then
  echo "  [SKIP] R33 —— 本次是嵌套调用（第 4 参数 --no-nest），跳过再次嵌套以防无限递归"
  skipped=$((skipped+1))
else
  bash "$SELF_DIR/i5-bidirectional-test.sh" "$HOME_DIR" "$JUDGE" "$NEWTMP" --no-nest > "$OUT33" 2>&1
  r33=$?
  # ② 断言 rc ∈ {0,1}（2=拒跑，126/127=没启动，一律失败）**且**输出必须有结论行
  case "$r33" in 0|1) pass … ;; *) bad … ;; esac
  grep -q '双向测结论' "$OUT33" && pass "子进程真的跑完了" || bad "「没跑成」被当成了「没拒跑」"
fi
```
并新增 **`skipped` 计数器**，结论行改成 `全通过（0 失败 · 跳过 N 项）` —— **跳过必须可见**。

【6】F-H5 的修法：★ **换一个子串不是修法**（这一条我当场被自己的夹具打回两次）

**第一次**：原口径 `grep -vc ' OK '` 数的是「**不含子串 ` OK `** 的行」——
detail 里出现 ` OK ` 的 FAIL 行会被**漏数**。我把它换成 `grep -cE '(FAIL|UNVERIFIED)'`。
**结果：21 条假红。** 因为
```
[I6] status 取值合法   OK   全部 status ∈ {OK/FAIL/ASK/PROGRESS/BLOCK}
                                                  ↑ 这个 FAIL 让每一条 OK 行都被算成非 OK
```
**第二次**：R35 的 `mustnot` 我写了 `I6.*FAIL` —— 同一个坑，
**`I6.*FAIL` 对本判据永远不可靠**（它的 OK detail 必然列出枚举）。

**根因**：`detail` 是**自由文本**，任何状态词都可能在里面出现。
**判据的输出格式是固定的**（`[Ix] ` + `name.padEnd(26)` + `state.padEnd(12)` + `detail`），
所以**状态就在第 31 列起**（`[I1] ` 5 列 + 名字补齐 26 列）—— **按位置取，不猜内容**。
```bash
pre=$(printf '%s\n' "$full" | node -e '
let s = "";
process.stdin.on("data", (d) => { s += d; }).on("end", () => {
  const n = s.split("\n")
    .filter((l) => /^\[I[0-9]+\]/.test(l) && !/^\[I5\]/.test(l))
    .filter((l) => /^(FAIL|UNVERIFIED)$/.test(l.slice(31, 43).trim()))
    .length;
  console.log(n);
});')
```
  用 node 而不是 awk/grep 的理由写进注释：**JS 的 `padEnd` 按码元补齐，node 的 `slice` 也按码元 ——
  同一套语义**；而 grep 的 `.` 在不同 locale 下按字节或按字符，数不准中文名字。

新增 **R36 元断言**：把**三个口径**放在同一段合成输出上跑，**必须只有口径三是对的**：
```
真值应为 1（一条 FAIL）
口径一 pre=0（漏数：detail 里的 ' OK ' 把 FAIL 行洗白了）
口径二 pre=2（假红：枚举表里的 'FAIL' 把 OK 行染红了）
口径三 pre=1 ✔
```
