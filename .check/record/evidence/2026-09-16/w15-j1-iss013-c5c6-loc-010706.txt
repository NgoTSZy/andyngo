【2】修法

**(a) `addRef` 记录每一处的来源**（`lines` 与 `sites` 平行）：
```js
function addRef(map, key, info) {
  const cur = map.get(key);
  const site = { line: info.line, srcFile: info.srcFile, srcLn: info.srcLn };
  if (!cur) { info.sites = [site]; info.lines = [info.line]; info.count = 1; map.set(key, info); return; }
  if (!cur.sites) { cur.sites = [{ line: cur.line, srcFile: cur.srcFile, srcLn: cur.srcLn }]; }
  if (!cur.lines) { cur.lines = [cur.line]; }
  if (!cur.lines.includes(info.line)) { cur.lines.push(info.line); cur.sites.push(site); cur.count = cur.lines.length; }
}
```
两处 `addRef` 调用点各加 `srcFile: L.srcFile, srcLn: L.srcLn`。

**(b) 报错改用 `siteOf` / `sitesOf`**（C5 两处 + C6 三处）：
```
-   r.fails.push('行 ' + info.line + '：引用了不存在的路径：' + key + …
+   r.fails.push(siteOf(info.sites && info.sites[0]) + '：引用了不存在的路径：' + key + …
-     (info.count > 1 ? ' · **该路径在文档里共被引用 ' + info.count + ' 处**（行 ' + info.lines.join(', ') + '）' : ''));
+     (info.count > 1 ? ' · **该路径在文档里共被引用 ' + info.count + ' 处**（' + sitesOf(info) + '）' : ''));
```

**(c) ★ 差点犯的错：抽成唯一一份实现。**
第一版我写的 `siteOf` 是**内联**同一个表达式：
```js
const siteOf = (s) => (!s ? '?' : (s.srcFile ? relName(s.srcFile) + ':' + s.srcLn : String(s.line)));
```
而第 287 行的 `loc(L)` 内联的**是同一个表达式** —— 这就是 `.check/fileset.js` 开头那句警告：
> 「为什么单独一个文件：… 都要它。**复制两份就会静默分叉** —— 而分叉最危险的地方在于它不报错。」

改为**一份实现、两个调用者**：
```js
const fmtLoc = (srcFile, srcLn, fallback) => (srcFile ? relName(srcFile) + ':' + srcLn : String(fallback));
const loc    = (L) => fmtLoc(L.srcFile, L.srcLn, L.i + 1);      // 给人看的（C1–C4/C7/C8 已在用）
const siteOf = (s) => (!s ? '?' : fmtLoc(s.srcFile, s.srcLn, s.line));   // C5/C6 的引用点
```
C6 的 `tloc` 也改成调 `fmtLoc`。

**(d) 自述随之更新**（第 1344 行那句「行号现在是 `文件:行`」**从假变真**）。
