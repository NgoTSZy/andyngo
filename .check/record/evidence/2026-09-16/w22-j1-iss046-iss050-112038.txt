§1 ISS-046：`[98]` 的「未到点」是把「正在跑」读成「没发生」

修前：`host-log.js` 的 `RE_AUTO` 只匹配 `terminal run record written`，
所以 `autoRuns` 只含**已结束**的运行。2026-09-16 那轮 automation 的
`startRunRecord`（01:05:34.340Z）与 `session attached`（01:05:34.371Z）**都在**，
只是终态（01:23:45.095Z）当时还没写 → `[98]` 报「0 次 · 未到点」，
SEAL v6 §六 据此写成「宿主日志窗口内**没有**本 automation 的运行记录」。
**它是有运行记录的。正确的说法是「没有终态记录」，不是「没有运行记录」。**

修法（**最小**）：
- `host-log.js` 新增 `RE_AUTO_START`（`startRunRecord written automationId=…, startedAt=…`）
  与 `out.autoStarts`。**不并入 `autoRuns`** —— 判定逻辑只该看终态，
  混进去会让「跑了一半」被 `pairRunWithLedger` 当成「跑完了」（假绿）。
- `pairRunWithLedger` 新增 `opts.starts`：`!last` 分支拆成两支 ——
  有起点 = **正在跑**（或那一轮崩了没落终态）；都没起点 = **未到点**。
- `acceptance.js` 的 `[98]` 明细加「start N 条 / 终态 M 条」，N > M 时明写「**差 X = 正在跑**」。
- `selftest-host-log.js` 新增第 **54/55** 条（解析层 + 判定层各一条）。
- `baseline.json` 的 `selftest.total/hit` 53 → **55**。

§3 ISS-050：候选规则有一半是错的，而且是**探针第一次跑就照出来的**

问题陈述（原文）：`issues.md` / `decisions.md` / `changes.md` 的**行**从来没被任何判据解析过
（I1–I7 只解析 `eventlog/`）。ISS-048 那一行三个片段被 shell 吃掉、留下空洞，
而**全部判据都报绿**（`newid.js --check` exit 0 · `andyngo-integrity.js` 14 OK / 0 FAIL）。

候选清单原本五条：① 前缀+3位号 ② 字段数下限 ③ 空括号对 ④ 连续两空格 ⑤ 记录区无前缀行。

**第一版探针扫三份真记录 → 命中 44 处，全部是合法内容：**
- `()` / `[]` / `""` / `''` 在记录里是**代码**的常态（`require()` / `f1[0]` / `Array.isArray(f1)` /
  `--get <路径> <vN>`），**不是空洞**；
- `` ` ` `` 会命中「两个代码段之间隔一个空格」（`` `a` `b` ``）；
- 「连续两空格」在**正例（ISS-040）与反例（ISS-048）里都出现** ——
  **一个在正例与反例里都成立的信号，区分度是 0。**

**结论：③④ 被否决，只留 ①②⑤（+ 制表符）。**
**一条一上线就假红 44 次的判据会被训练成忽略（DEC-019）—— 那比没有判据更坏。**
被否决的那族留在 `probe-record-shape.js --holes`，附带量化理由（**35 次**）。

**还有一条分区规则是被假红逼出来的**：第一版把 `格式：…` / `序号从 001 起…` 这些**表头行**
判成「形状不明」，一次报 9 处假红。三份记录的表头都在**第一个 `---` 之前** ——
**判据必须知道文档的分区，不能只认前缀。**

§5 唯一实现 + 双向测（不让两份实现互相背书）

规则抽到 `.check/record-shape.js`（**纯函数，唯一一份**），
`andyngo-integrity.js` 与 `probe-record-shape.js` 若各写一份会**静默分叉** ——
探针报「5/5 抓住」而判据用另一套逻辑，于是「测过了」与「判据真的会红」是两件事
（同 ISS-007：**同源判据不算两个判据**；这里是**两份实现互相背书**，更糟）。

`probe-record-shape.js` 三个模式：
- `--scan`  判据（有命中 exit 1）：**I8/I9/I10**
- `--inject` 双向测：注入 5/5 全被抓 · 反向 5/5 全干净 · 已知边界 1/1 · **计数自检 1/1**
- `--holes` 被否决规则的量化误伤（35 次）

§6 ★ 样本自检当场抓到一个潜伏 bug（**写这一段是因为它差点漏过去**）

`scanText` 第一版用 `out[k] = (out[k] || 0) + 1` 统一计数，而 `out.stray` **已经是个数组** ——
一旦真出现 stray 行，`out.stray` 就被 `+1` 覆盖成**数字**，下一行 `.push` 直接抛
`TypeError: out.stray.push is not a function`。

**更坏的是它在真记录上看不出来**：三份记录当时 stray=0，数组从未被覆盖 → 判据照报 OK。
抓住它的是 `--inject` 里那份**手工可数的小样本**（第 7 行故意没有前缀）。
**修法**：显式分类 —— 数组类走 push、标量类走 ++、**认不出的类别单独计 `other`**（不与数组键撞名）。

同一段还有第二个错：`record` 被计了两次 → 打印「记录行 120」（真值 60）。
这个数字**只用于显示、没有任何判据读它**，所以它错了也没人会发现。
**与 ISS-046 同形：「只用于展示的数字」最容易腐烂，因为它不参与任何判定。**

§7 残留与未验（**不假装已覆盖**）

  也可能是作者本意，**无法从单行文本机械判定**。`--inject` 里显式钉着它（断言 MISSED）：
  **「假装已覆盖」比「承认没覆盖」危险。**
- **`--holes` 的 35 次是「当前三份记录」的数**，会随记录增长而变；**它不是一个阈值**，
  是「这一族规则现在有多不准」的**快照**。
- **`record-shape.js` 的 `SPEC` 里 `min` 是从表头抄的**：哪天表头加了列而 `min` 没跟着改，
  这条判据会**变松**（下限更低）而不是变红 —— **判据不会因为规格变化而自己报警。**
- **本判据不在 `acceptance.js` 里**，也不在 `andyngo-integrity.js` 里 ——
  它是**独立命令**。**没接进任何自动流程之前，它只是一条「可以跑」的判据。**

§9 三句

1. **「候选修法」是上一轮的我的猜测，不是结论。** ISS-050 原文写着「加一条逐行形状判据
   （前缀+3位号 · 字段数下限 · **无空括号对** · **无连续两空格**）」——
   实测这两条会假红 44 次。**规格里写下来的东西，也要被实测一遍才配叫规格。**
2. **改了冻结件，就等于把「验证过了」这句话变成一句没有指称对象的话。**
   本仓库已经因为这个作废过一次复验（CHG-061），这次是**第二次**踩到同一个坑 ——
   区别是这次在**改完之后、跑完验收之后**才发现，靠的是核对 md5 而不是靠记忆。
3. **「只用于显示的数字」不参与任何判定，所以它错了没人会发现** ——
   本轮两个 bug（计数翻倍、`out.stray` 被覆盖）都长在这个位置上。
   **展示层的正确性没有判据保护，只能靠样本自检。**
