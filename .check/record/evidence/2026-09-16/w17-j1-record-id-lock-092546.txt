【4】新工具 `.check/record/newid.js`（139 行 · md5 `2c5352a1b579847d8fab1e484f34a4cf`）

**设计三点**：
1. **一次命令**完成「读最大号 → +1 → 追加」，中途不落别的进程。
2. 互斥用 `open(lock, 'wx')` —— `wx` 是**原子创建**（O_EXCL）：文件已存在就抛 `EEXIST`，
   两个进程不可能同时拿到锁。**没有用「先检查是否存在、再创建」那种两段式写法** ——
   那正是本文件要修掉的形状。
3. 等待用 `Atomics.wait`（**node 主线程可用**，浏览器主线程才禁止），
   同步阻塞而不是 `setTimeout` —— 本进程必须在拿到锁之前**不往下走**。

**三态退出码**（同 DEC-013：跑不成 / 跑了且不合格 必须分开）：

| 码 | 含义 | 写入了吗 |
|---|---|---|
| 0 | 成功（stdout 打印一行 `ALLOC <号>`） | 是 |
| 3 | 锁超时（5s） | **没有** |
| 4 | 参数错 / **路径错** | **没有** |
| 5 | `--check` 发现重复号 | 是（`--check` 不写） |

### 5.3 ★ 新工具第一版**自己被本项目的老陷阱打回**（这条比 5.2 更值得留）
第一版把「锁创建失败」一律归到退出码 3，而 3 的文档含义是「**锁超时**」。实测第一次跑：
```
$ node .check/record/newid.js /tmp/tmp.Svsvhro3Pf/issues.md ISS - "x"
锁创建失败（非占用）: ENOENT          ← 6 个进程全 rc=3
```
**真因不是锁被占，是路径不存在**：`mktemp -d` 给的是 `/tmp/tmp.XXXX`，
原样传给原生 `node.exe` 会被解析成 `C:\tmp\...`（**本项目第 5 次踩，见 ISS-003**）。
→ **归因指向了错的地方**（同族 ISS-013 / ISS-018 / ISS-035 / W9-N3，**第 5 次**）。
**修法**：非 `EEXIST` 一律归到 **4「参数/路径错」**，并把**目标文件与锁文件两条路径都打出来** + 给出 cygpath 提示。复验：
```
$ node .check/record/newid.js /tmp/tmp.Svsvhro3Pf/issues.md ISS - "x"
ALLOC-FAIL 不是锁占用（ENOENT），未写入
  目标文件: /tmp/tmp.Svsvhro3Pf/issues.md
  锁文件:   /tmp/tmp.Svsvhro3Pf/issues.md.lock
  提示: 给原生 node.exe 传路径必须是 Windows 形式（Git Bash 下先 cygpath -m）
EXIT=4
```
**这就是「自己造的尺子先量自己」** —— 一个用来消灭归因错误的工具，
第一版就犯了一次归因错误，而且是**跑出来的**、不是审出来的。
