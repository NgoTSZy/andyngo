【3】「73 项失败」是怎么来的 —— 本留证的重点（ISS-015）
我第一次复跑时**没带参数**（`bash .check/tests/i5-bidirectional-test.sh`），当时的脚本是
  HOME_DIR="$1"; JUDGE="$2"; TMP="$3"
**缺参不报错，继续跑**。原始输出开头：
  cygpath: can't convert empty path
  mkdir: cannot create directory ‘’: No such file or directory
  ===== I5 v3 双向测 =====
  --- R1 D3：豁免表缺失 → 必须点名 EVT 005 与 EVT 007 ---
  cp: cannot stat '/.check/record/eventlog/2026-09-15.txt': No such file or directory
  cp: cannot stat '/.check/record/exemptions/2026-09-15.md': No such file or directory
  find: ‘/.check/record/evidence/2026-09-15’: No such file or directory
  sed: can't read /r1/record/eventlog/2026-09-15.txt: No such file or directory
  rm: /r1/record/exemptions/2026-09-15.md: No such file or directory
尾部：
  双向测结论: 有 73 项失败

判定：**这不是判据的缺陷，是测试在拿不到参数时不拒跑** —— 把「根本没跑成」伪装成
「跑了 73 条红灯」。`$HOME_DIR` 空 → 路径退化成 `/.check/record/...`（根目录下）；
`$TMP` 空 → 夹具落在 `/r1` `/r3` 之类根目录。所有 cp/find 全失败，日志为空，
于是每条断言都报「缺 X」。

为什么这条值得单独记账：
  · 形状与 MEMORY 里那条 hook 教训**同族** ——「一条永远红的断言会训练人忽略红色」。
    一条会这样撒谎的测试比没有测试更坏。
  · 我自己就是被它骗的那一个：我第一反应是「判据退化了」，直到看见 `cygpath` 那行
    才回头查调用方式。**「判据报红时先怀疑判据自己」这条原则，本轮第三次生效。**

修法（两条，已落盘）：
  ① 三参数可省，按脚本自身位置推导：
       SELF_DIR=$(cd "$(dirname "$0")" && pwd)
       HOME_DIR="${1:-$(cd "$SELF_DIR/../.." && pwd)}"
       JUDGE="${2:-$HOME_DIR/.check/andyngo-integrity.js}"
       TMP="${3:-$(mktemp -d)}"
  ② 推导结果不自洽 → **exit 2 拒跑**，绝不进入断言循环：
       记录根无 `.check/record/eventlog`  → exit 2
       判据文件不存在                      → exit 2
       临时目录不可用                      → exit 2
  **拒跑(2) 与 失败(1) 与 通过(0) 是三种状态，退出码必须分开** ——
  把「没跑成」和「跑了且不合格」混成一个 1，就是让调用方无法区分「我命令写错了」
  与「被测对象坏了」。
