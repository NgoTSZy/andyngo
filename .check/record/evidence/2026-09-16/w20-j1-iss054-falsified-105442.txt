§0 一句话

`file-history/<conversationId>/<sha256(绝对路径·反斜杠原样)[:16]>@v<N>`。

§1 被推翻的结论（原文）
ISS-054（open/low）：「改 `host-log.js`/`selftest`/`baseline.json` **之前没有归档改前版本**，

§2 真机制（反推出来的，不是猜的）
规则：`sha256(<绝对路径，反斜杠原样，盘符大写>)[:16]` = `file-history/<会话id>/` 下的**目录名前缀**。
**交叉核对 2/2**（用 md5 确认归属，不是靠名字猜）：
  sha256(`C:\Users\<user>\.workbuddy-ai\.check\host-log.js`)[:16]          = `bc8a8f6310d6c715`  ✓
  sha256(`C:\Users\<user>\.workbuddy-ai\.check\selftest-host-log.js`)[:16] = `d9ba90655613dac5`  ✓
（第一次只对了一个文件，我差点当成巧合；**用第二个文件复核才把规则钉死** ——
 只验一个样本的规则，和没验过一样。）

§4 为什么会错（**这才是本条的重点**）
我查了 `git rev-parse` → `fatal: not a git repository` → 直接写成「不可回溯」。
**我只查了「一个我不熟悉的机制不存在」，就否定了「另一个我根本没查过的机制存在」。**
同一天里**同一种形状出现三次**：
  · `MEMORY.md` 那条「skill 层已清空 / 所有 `skills/…` 指针失效」—— 用旧快照否定磁盘现状（W18 已修）
  · ISS-051 的「判据读错通道」—— 用一个**必然为真的否定**代替真结论（W18 已修）
  · 本条 —— 用「不是 git 仓库」否定「有版本历史」（本轮修）
**共同形状：把「我没看见」写成「不存在」。** 这不是三个 bug，是一个思维习惯的三个实例。

§5 工具化（把「一条纪律」变成「一条命令」）
新增 `.check/file-history.js`（**只读**，127 行）：
  `--list <路径>`      列版本链（版本 / 会话 / md5 / 行数 / 块时间 / 是否 = 磁盘当前）
  `--get  <路径> <vN>` 打印第 N 版内容到 stdout（**只打印，绝不写文件**）
  `--hash <路径>`      只打印历史 hash
退出码三态（同 DEC-013）：`0` 找到 · `1` 该路径无历史 · `4` 参数错。
**为什么 `--get` 不落盘**：不留「让检查不跑」的开关（DEC-023）；要不要重定向由调用方自己决定。
另留反推脚本 `.check/probe-history-hash.js`（68 行）作**物证**：下次 hash 规则若变了，跑它就能看出来。

§7 残留与未验（**不假装已覆盖**）
- 只有 `host-log.js` / `selftest-host-log.js` 两条链做过 **md5 级**核对 → 「**所有**文件都被留版」**未证明**
- `file-history` 是**产品侧**机制，**不在本仓库任何判据的覆盖范围内**（没有验收项读它）
  → 它哪天改了行为，本仓库**不会知道**（同 ISS-050 家族：判据的输入没有判据）
- 输出里的「块时间」是**块文件的 mtime**，不是版本产生时间（近似，已在表头标为「块时间」）
