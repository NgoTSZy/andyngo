§3 锁日志：设计要点（为什么只有这三个事件）
  记：acquire / takeover / release —— **只有状态变化**
  不记：status —— 它是只读命令，一个「读」不该写历史；且「当时过没过期」可由持有区间推出，
        记下来只会让日志随「谁看了它」而变化（**证据被读者污染**）
  行格式：`<ISO 秒级 Z> <ev> <who> [自由文本]`（前 3 字段机器可读；who 不含空格，与锁文件同口径）
  写不进（只读盘 / 盘满 / 权限 / 父目录不存在）→ try/catch 静默跳过：
        **绝不让「日志写不了」变成锁的一个新的失效模式**（同 DEC-013 三态分开的用意）

§6 ISS-119 现场：本机 `env` 是空操作存根
  command -v env  → /c/Users/<user>/.local/bin/env   （**不是** /usr/bin/env）
  该文件：328 字节 / 4 行 shell 存根 —— 只把 $HOME/.local/bin 加进 PATH，**不执行命令**，exit 0
  PATH 位置：/c/Users/<user>/.local/bin = 第 11 位 · /usr/bin = 第 14 位 → 存根**优先**
  三态实测：
    env WRITE_LOCK_LOG=… node .check/write-lock.js status   → 无输出 · rc=0    （假成功）
    env node .check/write-lock.js status                    → 无输出 · rc=0    （假成功）
    WRITE_LOCK_LOG=… node .check/write-lock.js status       → LOCK free · rc=0 （真执行）
  env --version → 空 ； /usr/bin/env --version → env (GNU coreutils) 8.32
  危害链：$L 空操作 → 锁**从没被创建** → 第 17 项内层守卫看不见锁 → **递归**
  实测规模：**60 个 bash.exe 在跑 write-lock-test.sh**；TaskStop 只杀最外层 → 靠逐个 Stop-Process 清干净
  二次污染：孤儿一直在抢同一把锁 → 「修好后」首跑 15/16 FAIL；手工复现同一序列**完全正常**
