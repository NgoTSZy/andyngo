W23 J9 · X5 的「静默跳过」改成可测的分类（ISS-091）
留证 w23-j9-x5-gone-counter.txt · 2026-09-16
======================================================================

一 · 怎么发现的（顺序：先量数，再定规则）
----------------------------------------------------------------------
收尾跑 `--scan` 时看到 X5 一行：

    被记录过 md5 的文件 26 个 · 最新记录与磁盘一致 21 · 已过期 4

**21 + 4 = 25，而总数说 26。** 按本仓库的铁律「**每一处数字变化都要能解释**」，
这个差 1 必须解释 —— 于是去读代码，发现 `x5()` 里这一句：

    let st; try { st = fs.statSync(p); } catch (e) { continue; }   /* ← 静默跳过 */
    if (!st.isFile()) continue;                                     /* ← 同样静默 */

**`continue` 把条目从统计里丢掉了，却不计数、不打印。**
它不是「报错」，是**「跳过了不说」** —— 判据自己的账对不上，而没有人会注意到。

写了一个只读诊断脚本（`.check/record/tmp/x5-diag.js`）复刻 X5 的提取逻辑，
把 26 个条目全部列出来。结果：

    CHG 行数 = 110 · 路径/改后md5 数不齐而跳过 = 0
    map.size（被记录过 md5 的文件）= 26
      一致 = 21 · 过期 = 4 · **静默跳过 = 1**
      校验：21 + 4 + 1 = 26

    ---- GONE（被 :278 静默跳过）----
      C:/Users/<user>/Desktop/andyngo  记录=e31bb2f1（CHG-106）  ← statSync 失败: ENOENT

**那 1 个就是 CHG-106 被空格截断的路径**（`C:/Users/<user>/Desktop/andyngo`），
它配的「改后 md5」`e31bb2f1` **实际上是改前 md5**（字段整体左移一位的结果）。

**★ 所以这一条不只是口径洞，它还是 ISS-090 的硬证据。**
ISS-090 当时写的是「**若那个路径真实存在就会报假红**」—— 那是**推理**；
现在实测拿到了它的另一半：**该条目确实进了 X5 的 map，带着一个错的 md5 值**，
只是因为路径不存在才侥幸没报红。**推理的一半被实测补上了。**


二 · 顺带解释 STALE 5 → 4（J6 之后的一次数字变化）
----------------------------------------------------------------------
J6（13:34）留证写的是「STALE=5 / same=18」。本轮是「STALE=4 / same=20 / gone=1」。
**逐条对上（不是「大概变了」）：**

  map.size  23 → 26   (+3)
    +1  `.check/probe-crossref.js`       （CHG-104 首次记录它的 md5；J6 时它在 CHG-102 里是「新增」→ 跳过）
    +1  `.check/record/exemptions/2026-09-16.md`（CHG-108 新建本日志的豁免表）
    +1  `C:/Users/<user>/Desktop/andyngo`（CHG-106 的截断路径 ← **就是上面那个 gone**）

  stale     5 → 4    (-1)
    −1  `.check/record/issues.md`：J6 时它记的是 CHG-062 的 `c38270fa`，
        而当时磁盘已是别的值 → STALE；CHG-107 重记为 `822c5a91` = 磁盘 → 转 SAME。

  same      18 → 20  (+2)
    +2  probe-crossref.js（CHG-104 记的就是磁盘值）· exemptions 表（CHG-110 记的就是磁盘值）

  **23 + 3 = 26 ✓ · 5 − 1 = 4 ✓ · 18 + 2 = 20 ✓** 三个数各自闭合。


三 · 修法（最小改动：只加一个分类，不改原有跳过行为）
----------------------------------------------------------------------
① 把「分类」提成**纯函数**，让它可被 `--inject` 测：

    const x5Classify = (rec, disk) => (disk === null ? 'gone' : (disk === rec ? 'same' : 'stale'));

② `x5()` 里用分类替代两处 `continue`：`gone` 进一个数组，**计数 + 打印**。
③ 让**账必须闭合**：note 里直接算 `same + stale + gone = ?` 并断言 `必须等于 map.size`，
   闭合打印 `✓`、不闭合打印 `✗ 口径漏了`。**以后再有静默丢失，这一行会当场说出来。**
④ 打印路径加 `GONE` 前缀（与 `STALE` 分开，不混在 report 里）。
⑤ `--inject` 加 3 条向量测 `x5Classify`。

**行为边界：原有「跳过」语义一字未改** —— 取不到的文件仍然不判红（X5 是 report-only），
只是**现在会说自己跳过了几个、是哪些**。**只做加法。**

五 · 如实标注的边界
----------------------------------------------------------------------
1. **本改动让 X5 自己变成 STALE 一条**（`记录=7847a6e9 磁盘=c0af3ffb（CHG-104）`）——
   这是**自指的、预期的**：CHG-111 会重记它的新 md5，下一轮即回到 SAME。**不是缺陷。**
2. `GONE` 里的 `C:/Users/<user>/Desktop/andyngo` 是**项目外**的截断路径，
   **本判据修不了它**（根因在 CHG 格式无转义 + 路径含空格 → ISS-090 仍 open）。
   本改动只是让**它每次跑都可见**，把 ISS-090 从「一条推理」变成「一个每轮出现的数字」。
3. `x5Classify` 只覆盖「取不到 / 一致 / 不一致」三态，**不判 md5 值本身对不对**
   （判不了 —— 判据不知道「应该」是多少）。
4. **豁免表那条口径洞仍在**：`GONE` 项**不可豁免**（没有豁免入口），也不需要 ——
   它不判红，只报告。**没有扩大豁免面。**

七 · 副产品：`newid.js` 的 WARN 启发式有一条**可复现的假阳性**（ISS-092）
----------------------------------------------------------------------
落 `ISS-091` 时 `alloc.sh` 打了：

    WARN 正文里有空括号对或连续两空格 —— 可能被 shell 吃掉了片段（ISS-048 的形状）

但这一条是**用 `@正文文件` 写的**，正文**根本没经过 shell**，不可能被吃掉。
实测定位（不是猜）：命中 `newid.js:178` 正则 `/（）|\(\)|「」|“”|""|【】|  /` 里的
**`\(\)`** 这一支，命中的是正文里的 **`x5()`** —— 我提到那个零参函数名时写的，
出现 **2 次**（index 280 / 872）。

**★ 所以这是一类系统性假阳性**：**正文里提到任何零参函数名（`x5()` / `main()` / `init()`）
都会触发** —— 而本仓库的正文**经常**提到函数名。**一条经常误报的 WARN = 一条会被训练成忽略的 WARN**
（DEC-019 家族，只是从「红」降级成了「黄」）。

**★ 同时纠正我自己一个差点写下的错结论**：我一度判断正则里的 `  `（双空格）分支是**死代码**
（因为第 174 行 `body.replace(/\s+/g,' ')` 会把连续空白折成单空格）。
**读代码后推翻**：第 174 行在 `if (body.charAt(0) === '@')` **分支之内**（`:165`）——
**只在 `@文件` 路径执行**。inline 路径下 `  ` 仍可存活，该分支**可达**。
**不是死代码。** 这正是本仓库反复踩的形状：**把「我没看见」写成「不存在」** ——
这次靠「读 `:165` 那行」而不是靠印象，才没写错。

**修法（本轮未做，理由写在下面）**：把 `\(\)` 收窄成「**前面不是标识符字符**的空括号」——
`/(?<![A-Za-z0-9_])\(\)/`，这样 `x5()` 不再误报，而真正的空括号对仍会报。
**为什么不顺手改**：① 它只是 WARN，**不拦写入、不影响功能**；
② `newid.js` 是**分配号的核心**，一切记录都过它，改它该有独立的一轮；
③ 更硬的理由 —— **本仓库自己的规矩是「判据与它的双向测必须一起跑」，
而 `newid.js` 目前没有 `--inject` 那类双向测**，先改就等于又一次「判据没有尺子」。
**所以本轮只登记、不改**（ISS-092 open，含实测与确切修法）。
